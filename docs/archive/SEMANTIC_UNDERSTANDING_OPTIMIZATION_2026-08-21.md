# 语义理解+知识库时效性优化 - 2026-08-21

## 问题背景

用户反馈真实场景：用户问"天津钓鱼政策"，系统基于知识库中 2023 年的旧文档回答，但现在已经是 2026 年，政策可能已变更。用户质疑："为啥你给我的答案都 23 年的？现在是 26 年了"

**核心问题：**
1. 用户没有明确说"2026年最新政策"，只问了"天津钓鱼政策"
2. 系统没有理解用户的真实意图（想要当前有效的政策）
3. 知识库有 2023 年旧文档，系统直接用了，没有意识到已过期
4. 没有提示用户"文档已过时 3 年，建议更新"

---

## 用户需求（已确认）

1. **语义理解问题意图** - 不只看关键词，理解用户真实需求
   - 问"天津钓鱼政策" → 理解为需要**当前有效的政策**（2026年）
   - 问"禁渔期规定" → 理解为需要**今年的规定**

2. **优先级调整** - 时效性问题的处理顺序：
   ```
   联网搜索（优先）
      ↓ 如果搜不到
   知识库（兜底，但要明确标注年份和过期警告）
      ↓ 如果知识库也没有
   拒绝回答 + 替代建议
   ```

3. **知识库过期检测** - 文档如果过期：
   - 强制联网搜索
   - 明确标注年份（"根据2023年文档（已过时3年）"）
   - 提示用户："建议上传最新文档或联网核实"

4. **联网+知识库结合** - 两者结合使用：
   - 联网搜索 2026 年最新信息
   - 知识库提供历史背景（标注过期）
   - 综合回答，明确区分新旧数据来源

## 解决方案

### 模块 1：问题意图理解

**文件：`docmind/intent_understanding.py`**

#### 核心思路

不只看明确的时间词（"2026年"、"最新"），而是通过语义理解判断问题性质。

#### 问题分类

**时效性强（需要最新数据）：**
- 政策法规：`政策、法规、规定、许可、申请、禁渔`
- 许可咨询：`能不能、可以吗、允许吗、能去、能钓`
- 当前状态：`哪里、现在、目前、开放吗、营业吗`
- 实时数据：`票房、股价、销量、转化率、用户数`

**时效性弱（可用旧数据）：**
- 基础知识：`什么是、定义、概念、原理、介绍`
- 历史事件：`历史、由来、过去、曾经`
- 技术方法：`怎么做、如何、教程、代码、实现`

#### 特殊模式识别

**地名+活动模式：**
```python
"天津钓鱼" → 需要当前规定（2026年）
"北京滑雪" → 需要当前规定
"上海露营" → 需要当前规定
```

#### 返回结果

```python
{
    'needs_latest_data': True,
    'confidence': 0.9,
    'reason': '涉及政策法规类问题（关键词：政策、规定），需要2026年最新规定',
    'topic_category': 'policy',
    'inferred_year': 2026,
}
```

### 模块 2：文档时效性检测

**文件：`docmind/doc_freshness.py`**

#### 年份提取

从文件名和内容中提取年份：
- 文件名：`天津市渔业管理条例2023年版.pdf` → 2023
- 内容：前 500 字符中的年份

#### 文档类型分类

```python
'policy'     # 政策法规：超过1年 → 高风险过期
'data'       # 数据报告：超过6个月 → 高风险过期
'tech'       # 技术文档：超过2年 → 中风险过期
'knowledge'  # 基础知识：不过期
```

#### 过期风险判定

