# 智能路由没省下钱，但我还是留着它：一笔诚实的账

> 系列第四篇。网上讲"大小模型路由"的文章，结局通常是"本地模型省钱又保隐私"的爽文。我也给自研 RAG 平台做了路由（云端主力模型 + 本地小模型分流），然后把账真算了——**结果第一步就打脸：纯寒暄分流只省下 0.7% 的成本**。这篇就讲这笔账怎么算、真实收益到底在哪、以及什么情况下你根本不该做路由。所有数字可复现（`scripts/cost_report.py`）。

## 一、动机与一个被忽略的事实

观察生产流量会发现：相当比例的请求是"你好""谢谢""在吗"这类寒暄/确认/超短追问。每一条都调云端大模型，付的是整条链路的价格（在我的计价假设下每千次对话约 1.84 元），换来的却是模型敷衍的一句"有什么可以帮您？"。

直觉方案：这些请求分流给本地 Ollama 托管的小模型——快、免费、数据不出域。直觉没问题，但直觉不等于账。

## 二、决策层设计：先讲机制再讲钱

路由决策做成了**纯函数**（`model_router.resolve()`），输入请求特征、输出目标后端，永不抛异常、完全可复现。优先级是一条固定链：

```
显式指定模型 > 多模态输入 > 工具调用 > 思维链需求
    > 寒暄白名单（分词全词匹配，防误伤）
    > FAQ 灰度分流（md5 分桶，同题恒定同后端，默认关闭）
    > 默认云端
```

三个非成本的设计决策，比成本本身更重要：

1. **多模态/工具调用/思维链强制走云端**。本地 1.5B 干不了这些，能力边界写死在决策层而不是靠模型"自己看着办"。
2. **降级预注册**。本地是主目标时，云端作为降级项预先挂好——本地端点挂了自动切云，而不是等报错再想。
3. **流式场景只在建流前切换**。一旦吐出第一个 token，绝不换后端——用户看到一半换文风的回答比慢两秒糟糕得多。

每条决策都打点：`docmind_llm_route_total{backend, reason}`，路由分布在生产上是可见的，不靠感觉。

## 三、实测：分流率与那笔打脸的账

用 62 条样本（寒暄组 15 + 知识组 47）跑 `resolve()` 实测：**寒暄组 73% 命中本地**（分词全词匹配挡住了"你好吗"这类疑似知识问题），知识组全部走云端，总分流率 17.7%。

然后是成本。按参数计价假设（知识问答输入 2000 tok/输出 400 tok，寒暄 20/30 tok，本地按 25W 功耗折电费）：

| 口径 | 全云端基线 | 智能路由后 | 节省 |
|---|---|---|---|
| 本样本集 62 次 | 11.39 分 | 11.32 分 | **0.7%** |
| 折算每千次查询 | 1.838 元 | 1.825 元 | 0.012 元 |

对，你没看错：**0.7%**。原因一想就通——寒暄请求虽然条数多，但单条 token 极少（20 进 30 出），在以知识问答为主体的账单里本来就不是成本大头。分流它们省下的钱，约等于抹布擦了一下游泳池边。

所以如果一篇文章告诉你"路由能省 90% 成本"，它要么把知识问答也塞给了小模型（效果崩给你看），要么没把账摊开。

## 四、那路由的真实收益是什么？

三个，全部实测可感，但都不直接体现在账单上：

1. **首响延迟**。寒暄请求走本地小模型，亚秒级吐字，弱网环境尤其明显（云端首响要吃一次完整往返）。对"体感快不快"的贡献远大于账面。
2. **数据不出域**。寒暄虽然不含知识，但仍是用户输入——私有化部署场景里"任何用户输入都不过外网"是一条干净的合规红线，路由让红线实现起来零成本。
3. **上游故障的缓冲垫**。云端限流/抖动时，本地通道还在接客。降级链的存在让"部分可用"替代"全不可用"。

**成本杠杆在另一个开关上**：FAQ 灰度分流。把高频知识问答（每条 2000+ 输入 token 的真金白银）按 md5 分桶灰度到本地模型/缓存答案，才是省大钱的地方——同一测算里把 FAQ 卸载比例打开，分流率从 17.7% 上到 46.8%。但它有前提：FAQ 命中的回答质量要有评测兜底（这正是[系列第二篇](https://github.com/Ice-Breaking/DocMind/blob/main/docs/blog/02-lora-query-rewriter-ab.md)那套 A/B 方法的用武之地）。

## 五、什么情况下你不该做路由

- **流量里寒暄占比低**：分流率个位数，工程复杂度白付（优先去做系列第三篇的缓存，收益确定得多）；
- **没有本地算力或运维精力**：Ollama 也要人管（模型更新、显存、崩溃重启），小团队不如把钱花在缓存和限流上；
- **指望路由省钱**：如你所见，纯寒暄分流省 0.7%——把它当延迟与合规工程，别当成本工程。

```bash
python scripts/cost_report.py   # 路由分布实测 + 成本测算，全部参数可调
# 假设（单价/功耗/token 量）都集中在 --help 里，按你的生产账单校准后复跑
```
